# IPv4、IPv6 与域名解析基础

标签：#技术知识 #网络 #IPv4 #IPv6 #DNS #域名 #部署

## 一句话总览

IPv4 和 IPv6 负责给网络设备提供地址；DNS 负责把人容易记忆的域名解析成 IP 地址；TTL 负责控制 DNS 解析结果可以被缓存多久。

一次典型的网站访问可以简化为：

```text
用户访问域名
  -> DNS 查询域名对应的 IP 地址
  -> 连接 IPv4 或 IPv6 地址
  -> 访问服务器上的网站
```

## IPv4 和 IPv6 是什么

IPv4 和 IPv6 都是互联网协议，用来给设备分配网络地址，让数据知道应该发送给谁。

IPv4 的地址长度是 32 位，例如：

```text
192.168.1.10
```

IPv6 的地址长度是 128 位，例如：

```text
2001:db8:abcd:0012::10
```

IPv6 的设计背景是 IPv4 地址数量有限。IPv4 理论上约有 43 亿个地址，但公网地址还会受到私有地址、保留地址等因素影响，实际可直接分配的公网地址更加有限。IPv6 的地址数量约为 `3.4 × 10^38`，基本可以满足长期使用需求。

## IPv4 和 IPv6 的主要区别

| 对比项 | IPv4 | IPv6 |
| --- | --- | --- |
| 地址长度 | 32 位 | 128 位 |
| 地址写法 | 十进制，点分隔，例如 `192.168.1.10` | 十六进制，冒号分隔，例如 `2001:db8::1` |
| 地址数量 | 约 43 亿个，数量有限 | 数量极多 |
| NAT 使用情况 | 家庭和公司网络中经常使用 NAT | 理论上不需要为了解决地址不足而使用 NAT |
| 广播机制 | 支持传统广播 | 没有传统广播，主要使用组播等机制 |
| 自动配置 | 常依赖 DHCP 等服务 | 支持更完善的自动配置能力 |
| 兼容情况 | 老设备普遍支持 | 部分老设备或网络环境可能不支持 |

可以把它们理解成两代地址体系：IPv4 像地址数量有限的旧电话号码系统，IPv6 则把地址空间扩展得非常大。

## IPv4 私有地址、公网地址和 NAT

家庭网络中，电脑、手机通常拿到的是私有 IPv4 地址，例如：

```text
192.168.1.10
```

路由器再通过 NAT，让多台设备共享一个公网 IPv4 地址访问互联网：

```text
电脑、手机
  -> 路由器私有 IPv4
  -> NAT
  -> 公网 IPv4
  -> 互联网
```

因此，私有 IPv4 只能在局域网或特定内部网络中使用，不能直接作为互联网中的全球地址。

IPv6 的地址空间足够大，设备理论上可以拥有全球唯一地址。不过“有公网 IPv6”不等于“完全暴露且安全”，仍然需要通过防火墙限制不必要的入站访问。

## 域名和 IP 地址的关系

IP 地址适合网络设备使用，但不方便人记忆。域名相当于 IP 地址的可读名称，DNS 则负责保存两者之间的映射关系。

例如：

```text
example.com -> 203.0.113.10
```

用户访问 `example.com` 时，浏览器通常先查询 DNS，获得服务器 IP，然后再连接服务器。

## 主机记录是什么意思

主机记录就是域名前缀，用来决定一条 DNS 记录对应哪个域名。假设注册的主域名是 `example.com`：

| 主机记录 | 实际域名 | 常见用途 |
| --- | --- | --- |
| `@` | `example.com` | 主域名 |
| `www` | `www.example.com` | 网站常用地址 |
| `api` | `api.example.com` | 后端 API |
| `mail` | `mail.example.com` | 邮件服务 |
| `*` | 未单独配置的其他子域名 | 泛解析 |

例如，主机记录填写 `api`，实际配置的是：

```text
api.example.com
```

主机记录不是服务器地址，也不是端口号，而是域名左侧的前缀。

## A 记录和 AAAA 记录

DNS 中最常见的两种 IP 地址记录是：

| 记录类型 | 指向的地址 | 示例 |
| --- | --- | --- |
| `A` | IPv4 地址 | `example.com -> 203.0.113.10` |
| `AAAA` | IPv6 地址 | `example.com -> 2001:db8::10` |

如果服务器只有公网 IPv4，通常配置 `A` 记录；如果服务器有公网 IPv6，通常配置 `AAAA` 记录。服务器同时支持 IPv4 和 IPv6 时，可以同时配置两种记录，这种方式常称为双栈。

一个常见配置示例：

```text
记录类型：A
主机记录：@
记录值：203.0.113.10
TTL：600
```

这表示：

```text
example.com -> 203.0.113.10
```

如果还希望 `www.example.com` 指向主域名，可以使用 CNAME：

```text
记录类型：CNAME
主机记录：www
记录值：example.com
TTL：600
```

结果是：

```text
www.example.com -> example.com -> 203.0.113.10
```

## TTL 是干嘛的

TTL 是 DNS 记录的缓存时间，全称是 `Time To Live`，单位通常是秒。

例如：

```text
TTL = 600
```

表示 DNS 解析器、运营商或其他中间节点可以缓存这条记录最多 600 秒，也就是 10 分钟。缓存命中时，它们可以直接返回之前的 IP，不必每次都重新查询权威 DNS 服务器。

TTL 主要影响两件事：

- DNS 查询的频率。
- 修改域名记录后，新地址传播到不同用户的速度。

TTL 不会直接决定网页加载速度，也不是域名有效期或服务器租期。它控制的是“域名解析结果缓存多久”。

## TTL 和真实网站访问

用户访问网站时，浏览器、操作系统、路由器、运营商 DNS 或其他递归 DNS 服务器可能已经缓存了域名解析结果。

如果缓存还没有过期，DNS 服务器可能继续返回旧 IP；缓存过期后，才会重新查询并获得新 IP。因此，TTL 较长时，修改服务器地址后，不同用户可能在一段时间内访问到不同的服务器。

需要注意，缓存时间从某个 DNS 节点获取记录的时间开始计算，不是从你修改记录的时间统一开始计算。所以实际切换不会严格在某个整点同时完成，而是会逐步生效。

## 更换服务器地址时会发生什么

假设原来的记录是：

```text
example.com -> 旧服务器
TTL = 86400
```

某个 DNS 服务器上午 10 点缓存了旧地址，缓存有效期为 24 小时。即使你中午把记录改成新服务器地址，这个 DNS 服务器仍可能继续返回旧地址，直到它自己的缓存过期。

如果旧服务器已经停止服务，那么仍拿到旧地址的用户可能暂时访问不到网站；已经拿到新地址的用户则可以正常访问。

这也是为什么服务器迁移时不能只修改 DNS，还要考虑旧服务器上的流量。

## 服务器迁移时的建议

1. 提前至少一个旧 TTL，把 DNS 记录的 TTL 降低到 `300` 或 `600`。
2. 等待旧的长 TTL 缓存基本过期。
3. 修改 `A` 或 `AAAA` 记录，指向新服务器。
4. 旧服务器先保留一段时间，避免仍访问旧地址的用户报错。
5. 确认新服务器和域名访问正常后，再把 TTL 调回 `3600` 或更长。

常见选择：

| 场景 | TTL 建议 |
| --- | --- |
| 正在配置、频繁修改解析 | `600` 左右 |
| 网站稳定运行 | `3600` 常见 |
| 很少修改、希望减少 DNS 查询 | 可以设置得更长 |
| 准备迁移服务器或切换 CDN | 提前降低到 `300` 或 `600` |

降低 TTL 不会让已经存在的旧缓存立即消失，所以必须提前降低，不能等到迁移当天才临时修改并期待所有用户立刻更新。

## 最后区分三种缓存

排查“改了域名但访问结果没变”时，要区分：

1. DNS 缓存：缓存域名对应的 IP，受 TTL 影响。
2. CDN 缓存：缓存网页、图片、接口响应等内容，通常需要在 CDN 控制台刷新或等待过期。
3. 浏览器缓存：缓存网页资源，也可能需要强制刷新或清理缓存。

TTL 只控制第一种，也就是 DNS 解析结果缓存。

## 一句话总结

IPv4 和 IPv6 是两种 IP 地址体系；域名通过 DNS 映射到 IP；主机记录决定映射哪个域名；A 记录指向 IPv4，AAAA 记录指向 IPv6；TTL 决定 DNS 解析结果缓存多久，因此更换服务器后，长 TTL 可能让部分用户在一段时间内继续访问旧地址。
